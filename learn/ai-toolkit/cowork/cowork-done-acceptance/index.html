Delegating and Reviewing Work in Cowork / 04

用 DONE 检查策略交付是否可接手

把复杂委派拆为交付、依据、下一步和例外，并据此验收。

建议 45 分钟 · 案例为虚构练习，不是实际业务数据。

交付必须帮助一个人作决定

委派策略任务前说清谁要决定什么、有哪些可选方向、什么资源受限。例如组织者决定下一季度活动频率，需要理解人力与参与需求，而不是一份泛泛行业趋势。给 Cowork 指定输入和截止点，要求在资料不足时列出限制，不额外替你联系参与者或作出公开承诺。

复杂任务可以先交选项备忘录，再交最终方案。中间评审检查问题是否找对；最终评审检查结论、行动与证据是否一致。批准一个分析方向不等于授权所有后续执行，尤其是发通知、改日程或采购。

本指南的 DONE 验收助记

DONE 在这里是独立定义的四项检查：D 是交付物（Deliverable），实际文件能否打开并回答决策问题；O 是原始依据（Origin），关键事实能否追溯到来源；N 是下一步（Next），建议由谁在何时做什么；E 是例外（Exceptions），未知、失败输入和限制是否明示。它不是评分工具，也不意味着四项存在就无需判断质量。

验收要留下通过与不通过原因

逐项把结论追到资料，抽查关键计算，再评估建议是否符合资源约束。若资料不足，交付一份有用的缺口清单也可能符合任务目标；需要明确它只是决策准备。对不通过项给具体修订要求，说明修改何处和如何复核，避免无限循环“再优化一下”。

Worked example / 原创案例

虚构案例：社区手工课季度安排

两名组织者可投入每月合计16小时。每场课程准备与现场共需8小时，候选方案是每月一场或两场；报名需求记录尚不完整。

可尝试的任务说明

请用这些虚构资料比较每月一场与两场课程，生成一页决策备忘录。两名组织者合计16小时/月，每场8小时，请展示容量计算，说明需求记录缺口。建议包含负责人、下一次检查时间及暂缓事项。按本指南 DONE 列出验收证据，不发送通知、不修改日历。

怎么看结果

  1. 两场需要16小时，刚好用满容量，没有留出异常处理空间；一场需8小时。
  2. 建议先做一场并记录候补需求，明确两场方案暂缓的依据不是需求不存在，而是资料不完整且无缓冲。
  3. 验收打开备忘录、核对计算与来源、检查行动负责人，并确认未读材料和需求未知写入例外。
Your turn / 动手练习

为一项虚构策略任务写委派说明与验收记录。

  1. 设定两个选项、一条资源约束和一个资料缺口。
  2. 要求生成决策文件，按 DONE 四项逐一检查。
  3. 对一个未通过项给修订要求，再确认改动。

验收清单

  • 文件明确回答选项选择，并说明代价。
  • 至少一条核心依据可回到指定材料。
  • 下一步有负责人和检查点，例外没有被藏在结论后面。

完成状态仅保存在当前浏览器；不代表工具或平台认证。

容易踩的坑

  • “做完一份报告”只是形式，验收应检查它能否支持指定决定。
  • 计划内列出发布通知，不代表本次已获得发送授权。
