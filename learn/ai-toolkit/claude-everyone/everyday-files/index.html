Claude Code for Everyday Work / 01

用一份通知学会文件协作

从简单文档开始，识别“回答内容”和“创建文件”的区别。

建议 30 分钟 · 案例为虚构练习，不是实际业务数据。

文件是能再次打开的成果

聊天里的文字方便讨论，文件适合保存、转交和继续修改。给 Claude Code 文件任务时，说明要生成什么、放在哪里、谁会阅读。先使用普通文本练习：它容易打开和对照。等你能检查内容，再尝试带复杂排版的格式；扩展名并不保证内部内容或排版已经正确。

一次任务只选择少量必要输入。把事实清单与写作要求分开：活动时间、地址、报名方式是事实；语气、字数和读者是表达要求。这样发现错误时，你能判断它误读了信息，还是写得不合适。

限制模型替你决定的部分

通知缺少退款规则时，要求标出待确认，不允许补造。活动宣传可能需要活泼语气，但热情不能改变人数上限或承诺。告诉它哪些原句必须保留，哪些部分允许重写。保存原始资料和新稿，让你有办法回看每一项事实的出处。

交付后进行事实巡检

先核对读者需要行动的信息，再检查文风。日期、地点、截止时间和联系渠道逐项对照原始清单。打开真实文件确认内容完整，再检查文件位置和名称。最后请工具解释改动与未知项，方便你接手；“已经完成”不能代替这些检查。

Worked example / 原创案例

虚构案例：修理咖啡馆报名通知

社区拟办修理旧台灯的活动，时间为周六14点，限12人，报名截止周四；尚未确定是否收费。

可尝试的任务说明

请根据这份虚构事实清单，新建一份给居民看的报名通知。写清时间、人数上限和截止日期，保留报名渠道原文。费用未定，请标注待确认，不猜价格。正文约200字，另外列出需要我确认的事项，原始清单不修改。

怎么看结果

  1. 将费用留在待确认列表，不用“免费”吸引报名。
  2. 正文以带什么、何时到、如何报名为顺序，读者能直接行动。
  3. 打开新文件，逐项核对12人和周四截止，确认未把报名成功写成保证有名额。
Your turn / 动手练习

给一个虚构活动准备事实清单和通知稿。

  1. 写五项事实和一项未知，指定不可修改的输入。
  2. 要求生成正文及待确认列表。
  3. 亲自打开文件，纠正一处含糊表达。

验收清单

  • 未知信息没有被填成确定事实。
  • 通知中的时间和人数与输入一致。
  • 新文件能独立阅读，包含报名行动说明。

完成状态仅保存在当前浏览器；不代表工具或平台认证。

容易踩的坑

  • 不要因为文字顺畅就跳过日期核对。
  • 要求生成文档时明确格式，避免只得到聊天回复。
