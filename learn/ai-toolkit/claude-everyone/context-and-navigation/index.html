Claude Code for Everyday Work / 02

让工具找到正确材料和版本

控制上下文范围，区分背景缺失、文件没读与任务不清。

建议 35 分钟 · 案例为虚构练习，不是实际业务数据。

上下文是它此刻能用的材料

你知道的事不一定已经进入工具当前上下文。项目文件存在，也不代表它每次都完整读取。开始任务时指出具体材料和用途，请它用自己的话复述依据。需要查看文件时，可使用当前界面提供的文件引用能力；具体入口会变，不必把某个快捷键当成理解工具的前提。

给背景时先放决定任务所需的信息。一个通知任务可能只需事实清单和旧通知样式，不需要过去一年所有讨论。材料太多会让相互冲突的旧意见混进新任务，也增加你检查结果的成本。

找错版本会放大后续错误

文件名带“最终”仍可能已经过期。让 Claude 列出候选版本、日期及差异，再由你指定当前权威版本。对暂时无法判断的冲突，要求报告并暂停相关结论。修改错误版本之后再复制结果，容易丢掉后来新增的细节。

续接任务要留下交接条

长任务分阶段结束时，保存简短交接说明：目标、采用版本、已经决定什么、剩下什么、成果位置。新一轮先读交接条，再核对当前文件。你可以问“这次任务的范围是什么”来检查理解；若复述不准确，先修背景，继续修改只会增加偏差。

Worked example / 原创案例

虚构案例：两版社区讲座安排

文件夹里有“讲座安排最终版”和日期更晚的“讲座安排修订”。前者18点开始，后者19点开始且增加无障碍入口。

可尝试的任务说明

先比较这两份虚构安排，列出时间、地点、入场方式的差异，不起草通知。请说明你需要我确认哪一份为准。确认后只使用选定版本，旧版用于解释差异。

怎么看结果

  1. 识别日期更晚只是候选依据，仍向负责安排的人确认生效版本。
  2. 确认采用修订版后，保留19点和无障碍入口，避免从旧版混入18点。
  3. 任务结束写交接条，注明本次采用的文件及仍待核实的报名截止时间。
Your turn / 动手练习

制造两份相互冲突的计划，练习指定权威版本。

  1. 修改一个时间和一个地点信息，保留不同版本名。
  2. 让工具先比较差异，再明确采用版本。
  3. 写交接条，并检查下一轮复述是否正确。

验收清单

  • 差异列表找到了两项冲突。
  • 新稿只采用已指定版本的事实。
  • 交接条能定位成果和一个未完成事项。

完成状态仅保存在当前浏览器；不代表工具或平台认证。

容易踩的坑

  • 长聊天不是可靠的版本说明，应保存已确认决定。
  • 反复强调“仔细阅读”不如指定文件和必须提取的字段。
