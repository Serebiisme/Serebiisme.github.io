Claude Code for Everyday Work / 03

分工要有交接口，记忆要能更新

把资料任务拆成独立结果，并保存少量稳定的协作背景。

建议 35 分钟 · 案例为虚构练习，不是实际业务数据。

先看任务是否真的独立

分工适合几个互不依赖的小任务，例如分别提取三份活动反馈。它们可以共享格式，最后再合并。若后一份必须等前一份决定，按顺序处理更合适。Claude Code 子代理能在独立上下文中工作，因此你应给每个任务完整的必要说明与返回要求。

委派不是“帮我看看”。给出输入、要回答的问题、输出字段和停止条件。比如要求记录反馈主题、原文来源和不确定处；看不到资料时应报告缺失，而不是自行编写合理答案。

合并时有人承担判断

让各代理提取信息，再由主任务检查重复、冲突和遗漏。同一位参与者的多次反馈不应算作多人意见。角色审查可以帮你发现问题，但不能替代真实使用者；模型生成的“用户视角”只能算推测，需要明确标注。

记忆放约定，材料放文件

把常用术语、读者和事实检查规则写进简短项目说明，可以减少重复解释。访谈全文和旧通知仍放资料文件，按需读取。Claude Code 的项目说明与自动记忆提供上下文，不保证每条要求都被严格执行。每次重要任务仍要复述关键规则，并定期清理已失效约定。

Worked example / 原创案例

虚构案例：三场阅读会反馈

三场阅读会的便笺格式不同，一位读者参加了两场；你要选下次讨论时长。

可尝试的任务说明

分别整理三场虚构反馈，统一返回来源编号、匿名参与者编号、关于时长的意见和情境。合并时按参与者去重，保留互相矛盾的反馈。只提出待验证选项，不把模拟用户意见当作实测。

怎么看结果

  1. 各份结果保留参与者编号，让合并阶段能识别重复。
  2. 发现短场适合午休、长场适合周末，决定按时段比较而非只算支持人数。
  3. 项目说明只记录匿名编号规则和来源要求；下次举办时间留在任务简报，避免变成长期记忆。
Your turn / 动手练习

给两份反馈设计委派说明和一份合并规则。

  1. 指定相同返回字段，并加入一个重复参与者。
  2. 检查合并过程如何处理重复与冲突。
  3. 写四行长期项目背景，移除一次性日期。

验收清单

  • 每份结果都有可追溯来源。
  • 合并后人数未重复计算。
  • 长期背景可以用于下次活动且无敏感个人资料。

完成状态仅保存在当前浏览器；不代表工具或平台认证。

容易踩的坑

  • 代理意见一致可能来自相同假设，不能当作独立验证。
  • 把所有历史资料塞进记忆，会让旧事实持续干扰新任务。
