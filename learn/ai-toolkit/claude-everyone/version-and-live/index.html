Claude Code for Everyday Work / 05

保存版本，再决定怎样分享

区分本地文件、版本记录、代码托管与网站上线。

建议 40 分钟 · 案例为虚构练习，不是实际业务数据。

保存与版本记录不同

保存让当前文件保留下来，版本记录帮助你知道它从哪里变化而来。Git 用提交保存选定变化的快照，分支允许尝试另一方向。你不必先熟记命令，可以请工具解释当前状态和准备记录的文件，检查范围后再保存版本。一次版本最好能用一句话说明它改好了什么。

修改前先检查是否有别人的未完成内容。让工具列出与本次任务有关的文件，并解释差异。不要把工作区全部文件都当作一次修改的成果；文件中可能含草稿、个人资料或暂存的秘密。

分享时先选受众和形式

发送文件、分享预览与公开网站满足不同需要。只给同事看，可能分享文档已经足够；让用户点选流程，则需要能运行的预览。GitHub 托管项目，并不意味着网站自动对外可用。选择平台前说清访问人数、访问限制和是否需要收集数据。

线上检查包含实际路径

发布前核对标题、链接、图片、手机布局和演示标记，明确谁有权撤回。发布后从分享地址重新访问，按照首次读者的路径检查一次。交付说明要写版本、地址、检查结果和已知限制。工具说部署成功时，仍需确认你拿到的地址对应本次版本。

Worked example / 原创案例

虚构案例：阅读会信息页

你已做好阅读会单页，想先给两位组织者看，再决定是否公开给居民。

可尝试的任务说明

请先说明当前单页的文件变化和可以分享的方式。为两位组织者准备预览，标明这是审核稿，检查活动日期和报名链接。请提供版本说明及撤回办法；正式公开发布等我明确决定后再做。

怎么看结果

  1. 确认预览是否需要访问限制，清理示例联系人和不该公开的内部备注。
  2. 组织者按手机读者路径检查，提出一处日期表达修改；完成后另存可识别版本。
  3. 批准公开后检查实际链接和版本一致，保留预览审核记录以及撤回负责人。
Your turn / 动手练习

为一个本地成品写版本说明和分享方案。

  1. 说明本次修改目标、涉及文件和已知限制。
  2. 选择文件分享、受限预览或公开网页，并写理由。
  3. 按首次读者路径列出上线前后检查。

验收清单

  • 版本说明能区分当前稿与上一稿。
  • 方案明确受众和公开范围。
  • 至少一项检查从实际分享地址开始。

完成状态仅保存在当前浏览器；不代表工具或平台认证。

容易踩的坑

  • 私有仓库不自动保证部署地址私有，分别检查访问设置。
  • 版本可恢复文件内容，但已发出的通知和用户操作未必能撤销。
