# AI 工具实战：中文原创练习册

编写：Serebii Labs。非原课程译版。所有案例为独立设计的练习。
操作工具、访问外链和部署需要联网。练习完成状态应以产物与验收记录为准。

## 用 Claude Code 完成产品工作

### 1. 先认清工作区，再允许改文件

让第一次文件任务留下清楚的输入、输出与修改范围。

任务：用三份虚构会议便笺完成一次新增文件任务。
1. 给每份便笺写日期和来源编号，故意加入一条尚未批准的建议。
2. 限定输入文件与输出位置，让 Claude 先说明操作范围，再生成摘要。
3. 对照原文检查结果并记录一次纠正。

验收：
- [ ] 三份输入的名称与内容都没有变化。
- [ ] 摘要至少有一条待决定事项，且未被写成承诺。
- [ ] 每项已确认事项都能定位到具体便笺。

本地页面：/learn/ai-toolkit/claude-pm/workspace-boundaries/

### 2. 把研究材料整理成证据链

区分原话、解释与产品假设，让综合结论接受抽查。

任务：写四段匿名访谈，其中一段与多数意见相反。
1. 明确一个待决定的产品问题，并给材料标上编号。
2. 要求输出证据表和两条条件化洞察。
3. 抽查所有被引用段落，补充模型遗漏的反例。

验收：
- [ ] 每条洞察至少包含一个来源编号。
- [ ] 输出明确记录了相反意见及其场景。
- [ ] 结论没有把四人样本写成全体用户的比例。

本地页面：/learn/ai-toolkit/claude-pm/research-evidence/

### 3. 把分工和记忆写成可维护约定

让代理独立处理明确任务，并让长期背景保持准确。

任务：对同一份小需求做两种独立审查，并写一份项目约定。
1. 给两个角色不同的检查问题与统一返回格式。
2. 整理冲突意见，写下采用或拒绝的依据。
3. 从本次任务中挑出三条长期规则，移除临时日期与未经确认结论。

验收：
- [ ] 两份审查意见都定位到需求的具体条目。
- [ ] 合并记录至少解释一个取舍。
- [ ] 项目约定不包含账户秘密或本周一次性任务。

本地页面：/learn/ai-toolkit/claude-pm/agents-and-memory/

### 4. 把 PRD 写成团队能作决定的文档

从问题与证据出发，补齐规则、异常路径和验收。

任务：为一个小功能写不超过两页的 PRD。
1. 选一个具体用户失败，附上两条虚构证据。
2. 补齐正常流程和三个异常状态。
3. 让另一位读者只凭文档执行验收，记录解释不一致处。

验收：
- [ ] 每项未知决定都有负责人或下一步。
- [ ] 至少三个异常情景有明确用户反馈。
- [ ] 验收能说明输入、操作与预期结果。

本地页面：/learn/ai-toolkit/claude-pm/prd-acceptance/

### 5. 先手算小样本，再解释产品数据

核对口径、分母与分组，避免用整齐图表掩盖推断错误。

任务：手算这组数据，并给报告加上一个限制说明。
1. 先用纸笔核对六个比例。
2. 要求 Claude 区分组内变化与人群构成变化。
3. 写出一项能帮助决策的补充数据需求。

验收：
- [ ] 总体结果为38%与32%，而非两个组比例的简单平均。
- [ ] 说明新用户占比变化，且没有因果断言。
- [ ] 补充需求对应一个明确疑问，不只是“需要更多数据”。

本地页面：/learn/ai-toolkit/claude-pm/small-product-data/

### 6. 让策略产生选择和停止条件

把资料整理为约束下的选项，形成可解释的产品取舍。

任务：围绕一个真实或虚构项目写一页选择备忘录。
1. 列两个互相争夺同一资源的选项。
2. 为三个评价标准分别写依据和未知。
3. 写出推荐方向、暂缓事项与一个停止条件。

验收：
- [ ] 推荐说明了至少一项机会成本。
- [ ] 所有事实都有来源或明确标为假设。
- [ ] 停止条件包含可观察事件和检查时间。

本地页面：/learn/ai-toolkit/claude-pm/strategy-choices/

### 7. 用 Nano Banana 视觉简报建立一致性

写清视觉用途、结构和风格，保留评审标准而不依赖偶然好图。

任务：为一个产品概念写两份只改变构图的简报。
1. 写明解释目标和三个必须固定的风格属性。
2. 分别设计横向流程和单场景特写，不调用图像模型。
3. 按理解速度与误解风险比较简报，选定一个。

验收：
- [ ] 两份简报有相同色板、材质与视角约束。
- [ ] 明确标注概念图，未暗示已上线的真实界面。
- [ ] 选取理由引用具体构图差异，而非只说更好看。

本地页面：/learn/ai-toolkit/claude-pm/visual-brief-style/

### 8. 把原型、Git 和发布连成可检查交付

用最小原型验证任务，并在公开发布前明确版本和影响。

任务：用纸面页面或本地原型演练一次小交付。
1. 选一个三步以内的用户任务并列出失败状态。
2. 修改一次界面，记录原因与前后行为。
3. 写一份交付说明，分清可运行、已检查与待发布。

验收：
- [ ] 完成说明没有把模拟操作写成真实交易。
- [ ] 至少检查一条正常路径和两条失败路径。
- [ ] 发布范围与恢复办法在公开操作前已明确。

本地页面：/learn/ai-toolkit/claude-pm/prototype-to-release/

## 非技术读者的 Claude Code 文件协作

### 1. 用一份通知学会文件协作

从简单文档开始，识别“回答内容”和“创建文件”的区别。

任务：给一个虚构活动准备事实清单和通知稿。
1. 写五项事实和一项未知，指定不可修改的输入。
2. 要求生成正文及待确认列表。
3. 亲自打开文件，纠正一处含糊表达。

验收：
- [ ] 未知信息没有被填成确定事实。
- [ ] 通知中的时间和人数与输入一致。
- [ ] 新文件能独立阅读，包含报名行动说明。

本地页面：/learn/ai-toolkit/claude-everyone/everyday-files/

### 2. 让工具找到正确材料和版本

控制上下文范围，区分背景缺失、文件没读与任务不清。

任务：制造两份相互冲突的计划，练习指定权威版本。
1. 修改一个时间和一个地点信息，保留不同版本名。
2. 让工具先比较差异，再明确采用版本。
3. 写交接条，并检查下一轮复述是否正确。

验收：
- [ ] 差异列表找到了两项冲突。
- [ ] 新稿只采用已指定版本的事实。
- [ ] 交接条能定位成果和一个未完成事项。

本地页面：/learn/ai-toolkit/claude-everyone/context-and-navigation/

### 3. 分工要有交接口，记忆要能更新

把资料任务拆成独立结果，并保存少量稳定的协作背景。

任务：给两份反馈设计委派说明和一份合并规则。
1. 指定相同返回字段，并加入一个重复参与者。
2. 检查合并过程如何处理重复与冲突。
3. 写四行长期项目背景，移除一次性日期。

验收：
- [ ] 每份结果都有可追溯来源。
- [ ] 合并后人数未重复计算。
- [ ] 长期背景可以用于下次活动且无敏感个人资料。

本地页面：/learn/ai-toolkit/claude-everyone/delegation-and-context/

### 4. 把“做得更好”改成一次具体迭代

定义读者任务，用可观察反馈修正一个小页面或文档。

任务：对一页虚构通知或纸面页面做两轮小修改。
1. 列出读者必须找到的三项信息。
2. 写一条包含现象和期望的反馈，完成第一轮。
3. 重走读者任务，再根据发现提出第二轮反馈。

验收：
- [ ] 反馈具体指向一个位置或句子。
- [ ] 两轮修改没有改变原始日期或报名条件。
- [ ] 最终版本可按同一清单复核。

本地页面：/learn/ai-toolkit/claude-everyone/requirements-and-iteration/

### 5. 保存版本，再决定怎样分享

区分本地文件、版本记录、代码托管与网站上线。

任务：为一个本地成品写版本说明和分享方案。
1. 说明本次修改目标、涉及文件和已知限制。
2. 选择文件分享、受限预览或公开网页，并写理由。
3. 按首次读者路径列出上线前后检查。

验收：
- [ ] 版本说明能区分当前稿与上一稿。
- [ ] 方案明确受众和公开范围。
- [ ] 至少一项检查从实际分享地址开始。

本地页面：/learn/ai-toolkit/claude-everyone/version-and-live/

## Cowork 的任务委派与成果验收

### 1. 把第一项任务限制在可检查范围内

分清资料访问和行动授权，用小任务验证协作方式。

任务：创建一个三文件的虚构练习任务，加入一条无关指令。
1. 为资料指定用途，并移除真实个人信息。
2. 只委派生成索引，观察计划与访问范围。
3. 核对索引和文件变化，记录发现的异常。

验收：
- [ ] 无关指令没有成为执行步骤。
- [ ] 索引能定位每份输入并指出一个缺失信息。
- [ ] 任务仅产生约定输出，原始资料未改变。

本地页面：/learn/ai-toolkit/cowork/cowork-first-task/

### 2. 文件分类和凭证提取要留下对应关系

保留原始文件，核对提取字段、重复凭证与金额合计。

任务：用四条虚构凭证信息做去重与汇总。
1. 给一张凭证做副本，再给另一张留一个模糊字段。
2. 要求生成映射表、记录与异常列表。
3. 手算总额，检查副本处理和未知项。

验收：
- [ ] 唯一凭证数为3，合计为78元。
- [ ] 两份纸张文件对应同一记录且都可追溯。
- [ ] 模糊日期没有被猜成确定日期。

本地页面：/learn/ai-toolkit/cowork/cowork-files-receipts/

### 3. 批量材料先校准，再扩到全量

建立覆盖清单和统一提取方式，让大批反馈保持可核查。

任务：制作六段虚构反馈并安排一次样本校准。
1. 准备重复反馈、反例和一段无法读取的占位材料。
2. 先处理两段，给分类纠正，再扩到其他可读内容。
3. 检查覆盖清单、去重结果和未分类项。

验收：
- [ ] 覆盖清单解释每份资料的处理状态。
- [ ] 用户数与反馈条数分别统计。
- [ ] 规则调整后，之前处理的样本也重新检查。

本地页面：/learn/ai-toolkit/cowork/cowork-feedback-corpus/

### 4. 用 DONE 检查策略交付是否可接手

把复杂委派拆为交付、依据、下一步和例外，并据此验收。

任务：为一项虚构策略任务写委派说明与验收记录。
1. 设定两个选项、一条资源约束和一个资料缺口。
2. 要求生成决策文件，按 DONE 四项逐一检查。
3. 对一个未通过项给修订要求，再确认改动。

验收：
- [ ] 文件明确回答选项选择，并说明代价。
- [ ] 至少一条核心依据可回到指定材料。
- [ ] 下一步有负责人和检查点，例外没有被藏在结论后面。

本地页面：/learn/ai-toolkit/cowork/cowork-done-acceptance/

## 用 Cursor 整理产品判断与工作流

### 1. 先划定工作区，再选择交互方式

让模型准确识别输入、输出和改动范围，完成一次可审阅的会议整理。

任务：自写六句含一项否决意见的会议记录，整理成一页行动表。
1. 建立输入与输出目录并写背景。
2. 先请求只读分类，再授权写入指定输出。
3. 抽查两行并修正一处歧义。

验收：
- [ ] 原记录内容保持可比对。
- [ ] 否决意见没有变成行动项。
- [ ] 每项行动都有来源或待确认标记。

本地页面：/learn/ai-toolkit/cursor-pm/cursor-workspace/

### 2. 让模板与规则各司其职

把一次发布复盘整理为下次可复用、可更新的工作流程。

任务：为你常做的周报或复盘制作一个模板与一份流程说明。
1. 列出五个必填字段及各自输入。
2. 写清缺失字段的处理与输出位置。
3. 用完整和缺失两种材料各跑一次。

验收：
- [ ] 两次输出遵循同一字段结构。
- [ ] 缺失材料被明确标记。
- [ ] 流程文件可让新同事独立复现。

本地页面：/learn/ai-toolkit/cursor-pm/cursor-workflows/

### 3. 把研究证据接到需求与评审问题

从互相矛盾的用户反馈形成一份有边界的需求草案。

任务：围绕一个提醒功能写八百字以内的需求草案。
1. 写四条虚构观察并给编号。
2. 定义一个目标和两项不做内容。
3. 请求两个视角质疑并逐条回应。

验收：
- [ ] 每项主要需求有证据或假设标签。
- [ ] 至少包含一个失败路径。
- [ ] 评审问题有明确处理状态。

本地页面：/learn/ai-toolkit/cursor-pm/cursor-research-prd/

### 4. 从可复算的数据到实验决定

分清漏斗、实验与相关性，写出有计算依据的实验复盘。

任务：用两组各十人的合成数据写一页实验复盘。
1. 列分配人数、完成人数和一项负面指标。
2. 手算两种差异后让模型复算。
3. 写出继续与停止的条件。

验收：
- [ ] 分母为原分配人数。
- [ ] 百分点与百分比区分清楚。
- [ ] 结论明确写出合成数据和小样本限制。

本地页面：/learn/ai-toolkit/cursor-pm/cursor-data-experiment/

### 5. 用取舍表写产品策略

把多条合理的方向压缩成可讨论、可推翻的策略选择。

任务：为一个虚构小团队比较三条产品方向。
1. 限定一个季度和固定人员。
2. 每个方向写证据、假设与代价。
3. 选择一项验证并写反转条件。

验收：
- [ ] 文档明确放弃至少一个方向。
- [ ] 每个评分都有理由或未知标签。
- [ ] 反转条件对应可观察的行为。

本地页面：/learn/ai-toolkit/cursor-pm/cursor-strategy/

### 6. 把 Nano Banana 图像用于产品沟通

完成一套有用途、有一致性约束且可审阅的原创视觉方案。

任务：写两幅相关场景的视觉简报，并完成一次单变量修订。
1. 列用途、共享约束与每幅动作。
2. 生成或手绘第一幅并记录缺点。
3. 只修一个缺点，比较前后版本。

验收：
- [ ] 两幅图的关键人物可识别为同一设定。
- [ ] 修订记录明确改变的变量。
- [ ] 图像标有概念用途且没有未实现功能暗示。

本地页面：/learn/ai-toolkit/cursor-pm/cursor-nano-banana/

## 用 Codex 把产品想法推进到可验收交付

### 1. 用文件与 AGENTS.md 建立工作约定

让一次产品任务读对材料、写对位置，并能检查项目约定是否生效。

任务：为一个虚构产品建立四份材料和一份短项目说明。
1. 写明目录、输入和输出范围。
2. 添加两条可观察的工作约定。
3. 用一份冲突材料运行整理任务。

验收：
- [ ] 模型能列出实际适用的说明文件。
- [ ] 原始资料与输出可分别打开。
- [ ] 冲突没有被悄悄合并成新事实。

本地页面：/learn/ai-toolkit/codex-pm/codex-files/

### 2. 拆分研究与评审，保留证据链

组织几项可独立研究的任务，并在合并时检查重复、矛盾与缺口。

任务：把一份十二条反馈的练习资料拆成三项研究。
1. 为每项写输入、问题和输出。
2. 用并行或顺序方式取得结构化结果。
3. 随机抽查三条发现并记录反例。

验收：
- [ ] 每条主要发现能回到原始材料。
- [ ] 任务没有共用写入目标。
- [ ] 汇总至少列出一个未覆盖问题。

本地页面：/learn/ai-toolkit/codex-pm/codex-research-review/

### 3. 让需求文档能够驱动验收

写出可实施、可质疑、可验证的预约候补需求。

任务：为场地或器材候补写一份五状态需求。
1. 定义一个主要目标和两项非目标。
2. 写状态转换及三条异常验收。
3. 让模型走两人竞争同一资源的故事。

验收：
- [ ] 每个状态都有进入与退出条件。
- [ ] 未知政策单独列出。
- [ ] 能够判断同一资源是否被重复分配。

本地页面：/learn/ai-toolkit/codex-pm/codex-prd/

### 4. 把数据分析写成可重算的决策备忘录

用微型合成数据区分观察结果、可能解释和决策条件。

任务：手写六行预约状态数据，形成一页决策备忘录。
1. 写数据字典和一行的单位。
2. 计算两个分母不同的比例。
3. 提出一项能够区分两种解释的补充数据。

验收：
- [ ] 记录总数与分类计数一致。
- [ ] 每个比例写清分子分母。
- [ ] 因果猜测没有混入观察结论。

### 5. 用决策主线组织策略与演示
