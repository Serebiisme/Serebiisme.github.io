Claude Code for Product Work / 01

先认清工作区，再允许改文件

让第一次文件任务留下清楚的输入、输出与修改范围。

建议 35 分钟 · 案例为虚构练习，不是实际业务数据。

工作区也是任务边界

Claude Code 可以读取文件、编辑内容和运行命令。因此，工作区不只是放资料的地方，也是你决定它能接触什么、这次要做什么的起点。准备一个仅含练习资料的文件夹，把原始材料、产出和决策记录分开。原始材料保存证据，产出允许反复改写，决策记录解释为何选择这个版本。

在给任务前先让它列出文件名、类型与可能用途。目录里出现“最终版”不代表它最新；日期和正文可能互相矛盾。明确指出权威版本，省下后续围绕错误背景进行的精细工作。

意图和权限要同时清楚

“整理一下”可能意味着重命名、移动或删除，也可能只是生成索引。把动作写成“读取这些文件，新增一份摘要”，并指定输出位置。权限设置控制工具能否行动，自然语言描述控制你期待的结果；两者不能互相替代。初学时先观察它的计划，确认没有越过任务范围。

看变化，而不只看回答

任务完成后打开真实文件，比较改动前后。检查引用是否还指向原文、原始材料是否存在、输出是否放在约定位置。让 Claude 列出新增和修改的文件以及未完成事项，这份变更说明能帮助你发现“聊天里说完成，文件里没有”的落差。涉及重要资料时保留可恢复副本。

Worked example / 原创案例

虚构案例：共享厨房的会议摘要

一个共享厨房项目有两份会议记录和一份旧排期。你只想确认下周试用准备，不想调整排期。

可尝试的任务说明

请先查看练习文件夹的目录，告诉我哪些文件可能与下周试用有关。确认后读取两份会议记录，新增“试用准备摘要”，包含已确认事项、待决定事项、每项的来源。旧排期只作为背景，不修改、不移动任何输入文件。

怎么看结果

  1. 先辨认会议时间与参会者，判断两份记录是否讨论同一场试用。
  2. 把“建议增加晚间场次”记入待决定事项；只有明确同意的事项才能进入已确认区。
  3. 输出后抽查两条来源，查看目录变化。旧排期即使与新建议冲突，也只报告冲突，不能自行改日期。
Your turn / 动手练习

用三份虚构会议便笺完成一次新增文件任务。

  1. 给每份便笺写日期和来源编号，故意加入一条尚未批准的建议。
  2. 限定输入文件与输出位置，让 Claude 先说明操作范围，再生成摘要。
  3. 对照原文检查结果并记录一次纠正。

验收清单

  • 三份输入的名称与内容都没有变化。
  • 摘要至少有一条待决定事项，且未被写成承诺。
  • 每项已确认事项都能定位到具体便笺。

完成状态仅保存在当前浏览器；不代表工具或平台认证。

容易踩的坑

  • 把整个个人文档目录当练习区，会让任务边界难以检查。
  • “别弄坏文件”没有说明哪些动作允许，改成可观察的限制。
