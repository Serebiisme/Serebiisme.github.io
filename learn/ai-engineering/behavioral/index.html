01什么是 AI 工程，与机器学习工程有何不同？中文解析

原题 / What is AI Engineering, and how does it differ from Machine Learning Engineering?

原理与边界

可从交付目标回答：AI 工程常把基础模型、数据、检索、工具与评估组合成用户可用系统，机器学习工程也涵盖训练、特征、部署和监测。两者有大量重叠，不能简单分成“只调用 API”和“只训练模型”。用真实工作说明自己负责的链路、质量标准与上线证据，比职位标签更有说服力。

02怎样判断一个问题需要 AI，还是传统软件？中文解析

原题 / How do you decide whether a problem needs AI or a traditional software solution?

原理与边界

先明确目标、输入变化和错误代价，建立规则或传统检索基线，再测 AI 是否带来可观收益。固定规则、精确计算和高风险确定性流程通常适合明确程序，开放文本理解可能适合模型。回答时用数据解释成本、维护和可靠性，允许混合方案；不能仅因技术热门便选择 AI。

03怎样测量 AI 功能的投资回报？中文解析

原题 / How do you measure the ROI of an AI feature?

原理与边界

从实际业务结果计算增量收益，例如节省有效工时、提高成功转化或减少损失，再扣模型、运维、复核和失败成本。用上线前基线或受控实验建立归因，避免把使用量与收入直接画等号。说明观察周期、假设与不确定性，长期维护和人工修正也要进入总成本。

04生产系统发生幻觉时，怎样处理？中文解析

原题 / How do you handle hallucinations when they occur in a production AI system?

原理与边界

按影响先止损，对高风险功能暂停或转人工，保存脱敏案例及配置并定位首次错误环节。检查证据缺失、过期来源、提示或模型行为，制定修复并加入回归。回答应说明如何通知相关团队、验证恢复及监测复发；不要把“降温度”当作全部措施，也不夸大无法证实的零幻觉承诺。

05怎样选择 LLM API 与自托管开放模型？中文解析

原题 / How do you decide between using an LLM API vs self-hosting an open-source model?

原理与边界

比较相同任务质量下的总成本、峰值延迟、数据要求、许可和运维能力。API 降低基础设施负担，自托管增加部署控制但需要容量、安全、升级和回滚。用业务流量与硬件实测支持选择，并说明质量或需求变化时的切换条件；不能只比较每百万 token 与显卡购置价。

07描述你调试表现差的 RAG 系统的方法。中文解析

原题 / Describe your approach to debugging a poor-performing RAG system.

原理与边界

用具体失败请求复现，检查文档解析、分块、权限、召回、重排、证据组织和生成各层。以人工选定证据替换检索判断生成上限，固定生成器再比较检索改动。回答用真实日志和分桶指标说明根因与收益，不能把所有问题归因于模型弱；未做过时明确提供方法而非个人经历。

12AI 系统超预算，怎样优化成本？中文解析

原题 / How do you approach cost optimization for an AI system that's exceeding budget?

原理与边界

先拆分模型调用、输入输出 token、检索、重试与人工成本，按任务查看浪费来源。尝试缓存、短上下文、路由、小模型和调用合并，每项都在保留集检查质量与延迟。回答给出成本基线和节省证据，同时保留安全门槛；只降低单次调用价可能因重试增加而提高总成本。

原题 / How would you approach building an AI feature with limited labeled data?

20PM 想上线边界情况幻觉率 15% 的功能，怎样沟通风险？中文解析

原题 / Your PM wants to ship an AI feature with a 15% hallucination rate on edge cases. How do you communicate the risk?

原理与边界

先解释 15% 的分母、样本和置信范围，估算边界情况占比与错误后果，不能当作总体错误率直接传播。展示真实失败及受影响用户，提出缩小范围、转人工或继续试点等可比较方案。用业务代价和明确发布门槛讨论，记录决策责任；严重风险不能由平均收益抵消。

22复杂 Agent 基准高 15%，简单 RAG 更易维护，怎样选择？中文解析

原题 / You need to choose between a complex agentic system that scores 15% better on benchmarks, or a simpler RAG pipeline that is easier to maintain. How do you decide?

原理与边界

先核查 15% 是相对提升还是百分点、是否对应真实任务且统计可信，再比较任务完成、副作用、费用、延迟与维护负担。需要行动或多步探索的任务可能受益于 Agent，直接问答可保留简单方案。用代表集与试点评估总收益，允许按任务路由，不能仅为更高榜单分数承担长期复杂度。
