# AI 学习离线课程库设计

## 目标

在 Serebii Labs 根站增加名为“AI 学习”的课程入口，并建立可持续扩展的课程专辑库。首门课程完整收录 Bojie Li 的《深入理解 AI Agent：设计原理与工程实践》中文版；用户首次联网进入课程库后，站点在后台缓存整门课程，缓存完成后可在断网状态下继续阅读。

## 范围

本次交付包含：

- 在 Serebii Labs 首页导航和实验货架中提供清晰的“AI 学习”入口。
- 新增 `/learn/` 课程专辑库，视觉语言沿用 Serebii Labs 当前的编辑式新粗野主义风格。
- 将 `bojieli/ai-agent-book` 中文版静态构建到 `/learn/ai-agent-book/`，保留引言、10 章正文、后记、思考题参考答案、配图、公式、代码块与章节导航。
- 新增 PWA 清单、Service Worker、离线缓存状态和更新状态；缓存完成后，课程库和第一门课程在断网时可访问。
- 保留并展示作者、原仓库、固定上游提交和 Apache License 2.0 授权信息。
- 建立课程清单和同步脚本，使后续课程可按相同约定加入。

本次不包含配套实验代码的在线运行环境，不缓存 GitHub、论文、视频等站外链接，也不自动跟踪上游每次提交。外部链接在联网时正常打开，断网时不属于可用性承诺。

## 信息架构

### Serebii Labs 首页 `/`

- 顶部主导航新增“AI 学习”，链接到 `/learn/`。
- 将实验货架的第一张占位卡改为可点击的“AI 学习”卡，副标题说明当前已收录 1 门离线课程。
- 站点统计从 `00` 更新为 `01`，文案改为已发布的可体验内容。
- 其他占位实验保持不变。

### 课程专辑库 `/learn/`

- 页头包含 Serebii Labs 品牌、返回首页入口和“AI 学习”标题。
- 首屏解释课程库定位：收藏可完整离线阅读的中文 AI 课程。
- 课程卡展示课程封面式图形、标题、作者、10 章、版本来源、缓存状态和进入课程按钮。
- 页面预留基于课程清单渲染更多专辑的结构，但不显示虚构课程。
- 页脚说明课程版权归原作者，Serebii Labs 仅提供离线镜像与阅读入口。

### 第一门课程 `/learn/ai-agent-book/`

- 直接使用上游 `web-astro` 的中文静态站点构建结果，以最大限度保留原书排版和阅读能力。
- 构建时设置 `ASTRO_BASE=/learn/ai-agent-book/`，确保页面、图片、字体和章节链接都使用本站路径。
- 上游现成 Astro 路由只覆盖首页和 10 章正文；构建叠加层使用同一 Markdown 渲染管线为引言、后记和思考题参考答案增加三条中文阅读路由。
- 不改写正文。对构建结果仅增加中文路由、离线注册所需元数据和清晰的来源、修改说明。
- 课程首页和课程库均提供原仓库链接、作者署名、上游提交及许可证入口。

## 课程数据约定

`learn/courses.json` 是课程库的唯一目录数据源。每门课程包含：

- `id`：稳定的路径标识，本课程为 `ai-agent-book`。
- `title`：课程公开标题。
- `author`：原作者名。
- `route`：站内课程根路径。
- `sourceRepository`：原仓库 URL。
- `sourceCommit`：本次离线镜像对应的完整 Git 提交 SHA。
- `license`：SPDX 标识，本课程为 `Apache-2.0`。
- `chapterCount`：正文章数，本课程为 `10`。
- `offlineManifest`：该课程完整离线资源清单路径。

新增课程时只增加真实课程条目和相应静态产物，不创建“即将上线”假数据。

## 上游同步与构建

首版固定使用上游提交 `c8963443736004412692b1af7706c89096d46e4e`（2026-09-17），构建环境要求 Node.js `>=22.12.0`。仓库保留一个可重复执行的同步脚本。脚本按以下顺序工作：

1. 从 `https://github.com/bojieli/ai-agent-book.git` 获取已明确记录的上游提交。
2. 在临时目录中安装 `web-astro` 的锁定依赖，并运行其测试、类型检查和静态构建。
3. 使用 `/learn/ai-agent-book/` 作为 Astro base 路径。
4. 用新构建完整替换该课程的生成目录，但不触碰其他课程和首页文件。
5. 复制 Apache 2.0 许可证，生成来源与修改说明。
6. 枚举生成目录中的所有同源资源，生成版本化离线资源清单。
7. 运行本站契约测试，确认入口、章节、资源路径、许可证和离线清单完整。

脚本默认使用固定提交而不是 `main` 浮动版本，避免在未审查时把上游变化直接公开。更新课程必须显式修改提交 SHA、重新构建、审查差异并形成新的本站提交。

## 离线机制

Service Worker 的作用域限定为 `/learn/`，不接管 Serebii Labs 首页和其他未来实验。

- 安装阶段仅缓存课程库外壳、课程清单、离线状态脚本和错误页，保证 Service Worker 安装可靠。
- 用户进入 `/learn/` 后，页面向 Service Worker 请求缓存当前课程资源清单。
- Service Worker 逐项缓存第一门课程的所有 HTML、CSS、JavaScript、字体和图片，并把已完成数量回传给页面。
- 页面显示三种确定状态：“正在准备离线内容（完成数/总数）”“已可离线阅读”“离线准备失败，可重试”。只有全部资源成功写入版本缓存后才显示完成。
- 同一版本已经完整缓存时不重复下载。课程版本变化时建立新缓存，完成后再删除旧版本，避免更新过程中破坏已有离线副本。
- 课程导航采用缓存优先、联网回源并更新缓存的策略；课程库外壳采用联网优先、缓存回退策略。
- 对不属于 `serebiisme.github.io/learn/` 的请求不缓存、不拦截。

课程缓存完成是“可离线”的唯一成功标准；仅注册 Service Worker 或缓存当前页面不算完成。

## 文件边界

- `index.html`：仅负责根站入口和统计更新。
- `learn/index.html`：课程库页面和离线状态界面。
- `learn/styles.css`：课程库视觉样式。
- `learn/app.js`：读取课程清单、注册 Service Worker、展示缓存进度。
- `learn/courses.json`：课程目录与固定上游版本。
- `learn/manifest.webmanifest`：PWA 安装信息，名称为“AI 学习”。
- `learn/sw.js`：限定在 `/learn/` 的缓存与更新逻辑。
- `learn/offline.html`：课程资源尚未缓存时的离线提示。
- `learn/ai-agent-book/`：上游 Astro 生成的静态课程及授权文件。
- `overlays/ai-agent-book/`：将上游构建限定为简体中文，并补齐三条非正文章节路由的派生文件。
- `scripts/sync-ai-agent-book.sh`：可重复的上游抓取和构建入口。
- `scripts/generate-offline-manifest.mjs`：生成确定性的资源清单和版本哈希。
- `tests/site-contract.test.mjs`：验证站点结构、路径、授权和离线清单。

生成的上游课程文件与手写的 Serebii Labs 外壳严格分开，后续同步不得覆盖 `learn/index.html`、`learn/app.js` 或 `learn/sw.js`。

## 错误处理

- 上游提交不存在、依赖安装失败、上游测试失败或 Astro 构建失败时，同步脚本立即停止并保留现有课程产物。
- 任何课程资源未能缓存时，界面不得显示“已可离线阅读”；用户可以联网后重试。
- 课程清单无法读取时，课程库显示明确错误和原仓库备用链接，不渲染空白页面。
- 新 Service Worker 版本缓存不完整时保留旧缓存，避免已下载课程失效。
- 页面首次加载不支持 Service Worker 的浏览器时仍可正常在线阅读，并提示无法提供断网能力。

## 验证标准

发布前必须证明：

1. 根站首页同时存在顶部“AI 学习”入口和可点击课程卡。
2. `/learn/` 返回 HTTP 200，展示且只展示真实收录的第一门课程。
3. 课程的引言、10 章正文、后记和思考题参考答案均生成可访问页面。
4. 课程页面没有指向 `bojieli.github.io` 的运行时静态资源；所有阅读所需字体、脚本、样式和图片均为本站同源文件。
5. `LICENSE.txt` 与 `SOURCE.md` 可公开访问，署名、原仓库和固定上游提交可见。
6. 自动化契约测试、上游 Astro 测试与构建全部通过。
7. 在线浏览器完成整门课程缓存后显示“已可离线阅读”。
8. 浏览器切换到离线状态后，`/learn/`、课程首页和至少首章、中间章、末章可重新加载，图片、公式、代码样式与章节导航可用。
9. 恢复联网后页面仍可正常访问，并能识别未来版本更新。
10. GitHub Pages 最新构建对应本站发布提交，状态为 `built`，公开页面返回 2xx。

## 发布方式

继续使用现有 `master` 分支根目录的 GitHub Pages 发布方式，不切换 Pages 来源，不引入服务端依赖。生成的课程静态产物、课程库外壳、离线逻辑、测试和同步脚本均通过正常 Git 提交进入同一仓库。发布后保留提交 SHA 和上游提交 SHA，便于审计与回滚。
