01 / TEXT TO SETS

先切词，
再把重复的词合并。

这份实现的输入是两段文本，不是已经准备好的集合。它先调用与 BM25 共用的 tokenize，再用 Set 去重。为了看清过程，示例文本故意用空格分隔词。

02 / INTERSECTION OVER UNION

共同的部分，
占全部多少？

J(A, B) = |A ∩ B| / |A ∪ B|

交集 A ∩ B 是两边都有的词：{rag, 检索}，共 2 个。并集 A ∪ B 是两边出现过的所有不同词：{rag, 检索, 向量, 排序}，共 4 个。所以这两段文本的 Jaccard 相似度是 2 / 4 = 0.5。

这个比例是对称的：交换 A 和 B，交集与并集大小都不变，所以 J(A, B) = J(B, A)。

03 / THE SCALE

从 0 到 1，
边界要分清。

只要并集非空，Jaccard 一定落在 [0, 1]：没有共同词为 0；词集完全相同为 1；中间值表示有部分重叠。下图左侧的例子是两个分别有 3 个和 2 个词、彼此不重叠的集合。

04 / WHAT IT CANNOT SEE

它认得相同的词，
认不得相近的意思。

Jaccard 是词面重叠的尺子。两句话换了说法，即使意思接近，只要词集不重叠，分数仍可能是 0。反过来，两篇文本共享很多常见词，也不一定讨论同一件事。

同词频率 / 不计次数

检索 × 3 仍是一个词。

Set 只问“有没有”，不问“出现几次”。这让重复堆词不会直接抬高 Jaccard。

中文边界 / 取决于切词

空格也会改变结果。

当前 tokenize 会把连续汉字保留为一个词，并过滤长度为 1 的词；它不是语义分词器。

例如 "向量检索效果" 会得到一个词，而 "向量 检索 效果" 会得到三个词；在当前规则下，两组词没有完全相同的元素，Jaccard 会是 0。文本的意思没变，分数却变了。这说明分词方式是相似度定义的一部分。

05 / IN RETRIEVAL

为什么 MMR
会用到它？

MMR 每轮挑下一条检索结果时，会计算候选与已选结果的 Jaccard 相似度，并取最大值作为“重复惩罚”。它要避开的是与任何一条已选内容太像的候选。

Jaccard 不需要额外向量，适合作为轻量的词面去重信号；但它无法识别同义改写。读懂这把尺子后，再看 MMR 如何把相关性与多样性放到同一道公式里 →

06 / TAKEAWAY

记住分子和分母，
就记住了这把尺子。

The short version
“共同词占全部不同词的比例。”
  • 先处理：切词、转小写、去重，得到两个词集。
  • 再计算：|A ∩ B| / |A ∪ B|，非空并集时结果在 [0, 1]。
  • 空集合：并集为 0 时，当前代码直接返回 0。
  • 适用边界：它看词重叠，不直接理解语义；分词规则会影响结果。
