01 / THE PROBLEM

前几条都相关，
却像在说同一件事。

设想要选出 3 条检索结果。只按原有分数排序，会拿到 A、B、C；其中 A 和 B 的用词高度重叠。MMR 在保留 A 的同时，给重复内容一个惩罚，于是示例中改选 A、C、D。

02 / THE BALANCE

一边奖励相关，
一边扣掉重复。

MMR(d) = λ × relevance(d) − (1−λ) × maxSim(d, selected)

relevance(d) 是候选本来的综合检索分数；maxSim 是它与任意一条已选结果最相似的程度。取最大值，是为了防止一条候选只因与其他已选项不同，就掩盖了它和其中某一条几乎重复的事实。

奖励 / λ = 0.7

越相关，越加分。

当前实现把相关分数乘以 0.7。进入重排分支后，第一条直接取输入的首项；其后每轮用这个分数比较剩余候选。

惩罚 / 1−λ = 0.3

越重复，扣得越多。

候选与已选结果的最大 Jaccard 相似度乘以 0.3，再从相关项里减去。

0.7 / 0.3 是公式权重，不是最终分数里固定的“70% 相关、30% 多样”。如果相关分数和 Jaccard 的尺度不同，两项实际影响也会不同。这里的算例把相关分数放在 [0, 1]。

03 / THE RULER

重复度，用词集的
交集除以并集。

Jaccard(A, B) = |A ∩ B| / |A ∪ B|

实现会先用与 BM25 共用的 tokenize 处理两段文本，再转为集合：同一词出现几次只算一次。A 和 B 各有 4 个词，重叠 3 个，并起来有 5 个，所以 3 / 5 = 0.60。

两个空词集的并集大小为 0 时，代码返回 0，避免除以零。完全相同的非空词集得到 1，没有共同词则得到 0。

04 / GREEDY SELECTION

每选一条，
重算剩下的候选。

输入已按相关分数排列为 A、B、C、D，目标取 topK = 3。第一步直接选 A。第二步比较 B、C、D；第三步已有 A、C，再比较 B 与 D。每轮只拿当前 MMR 最高的一条，这就是贪心选择。

选择是局部的：它只保证每一轮挑当前最高分，不保证所有可能的 topK 组合里存在一个“全局最优”。已选集合一变，候选的 maxSim 也可能变，所以不能只计算一次 MMR 再排序。

05 / IN THE CODE

图上的每一步，
在代码里都有位置。

代码位置实际作用
selected = [results[0]]首项先入选；调用方需要先把结果按相关度排好。
while (selected.length < topK)没选够就继续，每轮看剩余候选。
remaining[i].score候选的综合相关分数。
Math.max(...selected.map(...))与每篇已选文本算 Jaccard，取其中最大值。
0.7 × relevance − 0.3 × maxSim计算本轮 MMR，并记录最高的候选。
selected.push + remaining.splice放入结果、移出候选池，进入下一轮。

还有一个容易漏看的快捷路径：如果 results.length <= topK，函数会直接返回原数组，根本不会进行 MMR 重排。上面的四选三算例才会进入循环。

这份实现用 Jaccard 的好处是无需额外向量，且复用 BM25 的 tokenize。代价是它只看词重叠；中文连续文本的切词效果也受当前规则限制。相似度计算次数大致随“要选的条数 × 剩余候选数 × 已选条数”增长，实际耗时还包含每次分词与建集合。

06 / TAKEAWAY

把结果集看成
一张逐步完成的拼图。

The short version
“每轮选最相关、又最不重复的下一块。”
  • 奖励：λ × relevance 保留与查询的关联。
  • 惩罚：(1−λ) × maxSim 避免贴近任一已选结果。
  • 顺序：先选输入首项，再逐轮重算剩余候选。
  • 边界：它是贪心重排；效果取决于分数尺度和相似度尺子。
